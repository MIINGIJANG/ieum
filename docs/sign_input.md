# 카메라 수어 입력 (시험판, `web/sign/`)

카메라로 수어를 하면 낱말을 알아듣고, 비슷한 질문을 찾아 이음에 묻는 **독립 페이지**다. 본 화면(`web/index.html`)은 건드리지 않았고,
완성도를 확인한 뒤 본 화면에 카메라 버튼으로 붙인다.

- 주소: `/sign/` (예: https://miingi-ieum.hf.space/sign/)
- 인식 모델·특징 변환은 팀원 SignBridge(github.com/BioCode67/signbridge) 것을 그대로 씀

## 흐름

```
카메라 → 관절 점 (Holistic 또는 가벼운 모드, 작업자 스레드, 기기 안)
     → 떨림 줄이기(One Euro) · 손이 150ms 안에 다시 잡히면 메우기
     → 손 움직임으로 낱말 끊기 (손 올림 → 손 내림 또는 0.35초 멈춤, 0.3~3초)
     → 낱말 인식 (ONNX, 특징 155개 × 32프레임) · 새 낱말(가르친 예시)과 비교
     → 확신 판단 (전체 단어 기준 확률 ≥ 25% 이고 1·2위 차이 ≥ 8%, 아니면 '?' 표시)
     → 질문 흐름으로 후보 다시 고르기 → 후보에서 골라 고치기
     → 문서 말로 바꾸기 (머리 + 보호 → 안전모, 입다 → 착용) → 비슷한 질문 3개 / 낱말로 바로 묻기 → 이음 /query
```

- 영상은 기기 밖으로 나가지 않는다. 서버에는 고른 질문 글자만 간다.
- 모든 단계는 화면의 '설정 (비교용)'에서 끄고 켤 수 있고, 평가 페이지가 같은 설정을 하나씩 바꿔 비교한다.

## 개선 내용 (예전 = 팀원 SignBridge 방식)

| # | 개선 | 예전 | 지금 |
|---|---|---|---|
| 1 | 낱말 끊기 | 0.25초마다 최근 **48프레임**(느린 기기면 10초어치)을 보고, 같은 낱말 2번이면 확정 | 손을 올린 순간부터 내리거나 멈출 때까지를 한 낱말로 잘라 **한 번** 인식 (`Segmenter`) |
| 2 | 평가 | 없음 | 관절 점만 녹화(영상 없음) → `eval.html` 이 설정 10가지로 다시 돌려 낱말·질문 정확도 비교 |
| 3 | 속도 | Holistic (얼굴 468점까지 계산), 화면 스레드 | 가벼운 모드(몸 lite + 손만, 손은 몸 손목에 가까운 쪽으로 왼·오른 구분, **기본**) · 작업자 스레드. 화면의 점·선은 떨림 줄이기 전 값으로 그려 늦게 따라가지 않게 |
| 4 | 확신 판단 | 산업안전 단어 안에서 확률을 다시 나눠 부풀려짐 (≥ 60%) | 전체 단어 기준 확률 + 1·2위 차이. 확실하지 않으면 '?' |
| 5 | 떨림·끊김 | 없음 | One Euro 필터, 손 끊김 150ms 메우기 (`FrameCleaner`) |
| 6 | 후보 다시 고르기 | 없음 | 낱말마다 후보 5개 중 우리 질문들에 같이 나오는 조합을 위로 (`rerank`) |
| 7 | 새 낱말 | 모델에 없는 말은 못 함 | 낱말마다 5번 녹화 → 모델 출력 모양이 가장 비슷하면 그 낱말 (재학습 없음, 기기에 저장, 파일로 공유 → `web/sign/custom_words.json`) |
| 8 | 깊이(z) | 사용 | 끄고 켜며 비교 (평가 페이지) |

## 평가 (`/sign/eval.html`)

1. `/sign/` 의 '정확도 평가용 녹화'에서 할 질문(과 낱말)을 고르고 녹화 → 관절 점 파일(JSON) 저장
2. 평가 페이지에 파일들을 넣으면 설정 10가지(새 방식·예전 방식·하나씩 끈 것)로 다시 돌려 낱말 찾은 비율·맞은 비율·질문 1순위/3순위 정확도

**가짜 녹화로 확인** (`data/eval/sign_synthetic/`, `python scripts/eval/make_sign_synthetic.py` — 우리 아바타 동작 데이터를 웹캠 관절 점 모양으로 바꾼 것, 예시 질문 5개):

| 설정 | 낱말 찾음 | 낱말 맞음 | 질문 1순위 | 질문 3순위 안 |
|---|---|---|---|---|
| 새 방식 (모두 켬) | 80% | 87% | 80% | 100% |
| 예전 방식 (팀원 그대로) | 17% | 40% | 0% | 20% |
| 예전 방식 + 산업안전 단어만 | 45% | 73% | 20% | 40% |
| 낱말 끊기만 예전 | 30% | 50% | 20% | 40% |
| 산업안전 단어만 끔 | 58% | 58% | 60% | 100% |
| 떨림 줄이기 끔 / 후보 다시 고르기 끔 | 80% | 80% | 80% | 100% |

⚠ 가짜 녹화는 사람의 웹캠보다 훨씬 깨끗하고, 동작 일부는 인식 모델의 학습 자료(AI Hub)와 겹칠 수 있어 **실제 정확도가 아니다.**
설정 사이의 차이(특히 낱말 끊기·산업안전 단어만)를 보는 용도. 실제 값은 팀원 녹화로 다시 재야 한다.
확신 판단·깊이·새 낱말은 가짜 녹화에서는 차이가 없었다 (새 낱말은 가르친 것이 없음).

## 파일

| 파일 | 내용 |
|---|---|
| `web/sign/index.html`, `app.js` | 화면 (설정·새 낱말 가르치기·평가용 녹화) |
| `web/sign/core.js` | 공통: 특징(팀원 `landmarks.ts` 그대로), 떨림 줄이기, 낱말 끊기, 인식·확신 판단, 새 낱말, 후보 다시 고르기, 질문 찾기, 예전 방식(`WindowCommitter`) |
| `web/sign/engines.js`, `landmark-worker.js` | 관절 점 엔진 (Holistic / 가벼운 모드), 작업자 스레드 |
| `web/sign/eval.html`, `eval.js` | 평가 페이지 |
| `web/sign/models/pose_landmarker_lite.task`, `hand_landmarker.task` | 가벼운 모드용 MediaPipe 모델 (6MB + 8MB, Apache-2.0) |
| `web/sign/custom_words.json` | 팀원이 함께 쓸 새 낱말 예시 (처음엔 비어 있음) |
| `web/sign/models/model.onnx`, `meta.json` | 낱말 인식 모델 (13,576개, 검증 정확도 78.2%, 25MB) — 팀원 저장소 `public/models/ksl-iso/` |
| `web/sign/models/holistic_landmarker.task` | 관절 점 모델 (14MB) |
| `web/sign/lib/mediapipe/` | MediaPipe Tasks Vision 0.10.35 (Apache-2.0) |
| `web/sign/lib/ort/` | ONNX Runtime Web 1.27.0 wasm (MIT) |
| `web/sign/domain.json` | 산업안전 단어 533개(말 270개), 수어 → 문서 말, 대체 표현 거꾸로, 질문 후보 49개 — `python scripts/data/build_sign_input_vocab.py` |

처음 한 번 약 60MB 를 받는다 (카메라 켜기를 누를 때만). 한 번 받은 기기는 본 화면의 오프라인 저장(`web/sw.js`)에 같이 들어간다.

## 산업안전 단어만

모델의 13,576개 중 우리 서비스에 나오는 말(동작사전·단어표·대체 표현·예시 질문·모범 답안·평가 질문의 낱말 + 질문할 때 쓰는 말)만 남겨
그 안에서 고르게 한다. 헷갈리는 후보가 줄어 정확도가 오를 것으로 보지만, **실제 수어로 잰 값은 아직 없다** (화면에서 끄고 켜며 비교).

모델에 없는 우리 말: 안전모·안전화·장갑·귀마개·보안경·교체·정화통·작업·착용·소음·교육·세척 등.
→ 있는 낱말 조합(머리 + 보호 → 안전모)이나 비슷한 말(입다 → 착용, 바꾸다 → 교체)로 문서 말을 찾는다.

## 남은 일

1. 팀원 몇 명이 예시 질문을 녹화해 평가 페이지로 실제 정확도 재기 → 기본 설정 정하기 (가벼운 모드를 기본으로 할지 등)
2. 모델에 없는 산업안전 낱말(안전모·장갑·귀마개·정화통 등)을 '새 낱말 가르치기'로 녹화해 `custom_words.json` 에 모으기
3. 완성도가 나오면 본 화면 입력창에 카메라 버튼

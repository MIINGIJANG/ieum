# 카메라 수어 입력 (`web/sign/`)

카메라로 수어를 하면 낱말을 알아듣고, 고른 낱말로 질문을 찾아 입력창에 넣는 **팝업**이다. 본 화면(`web/index.html`) 입력창의
카메라 버튼으로 열고, 시험 페이지(`/sign/`)도 같은 팝업(`web/sign/popup.css`·`app.js`)을 쓴다. 인식 모델은 본 화면 첫 로딩 화면에서
미리 준비하므로 카메라 버튼을 누르면 바로 카메라가 켜진다.

- 주소: `/sign/` (예: https://miingi-ieum.hf.space/sign/)
- 인식 모델·특징 변환은 팀원 SignBridge(github.com/BioCode67/signbridge) 것을 그대로 씀

## 흐름

```
카메라 → 관절 점 (Holistic 또는 가벼운 모드, 작업자 스레드, 기기 안)
     → 떨림 줄이기(One Euro) · 손이 150ms 안에 다시 잡히면 메우기
     → 손 움직임으로 낱말 끊기 (손 올림 → 손 내림 또는 0.35초 멈춤, 0.3~3초)
     → 낱말 인식 (ONNX, 특징 155개 × 32프레임) · 좌우를 뒤집은 것도 인식해 왼손잡이인지 판단 · 새 낱말(custom_words.json 예시)과 비교
     → 확신 판단 (전체 단어 기준 확률 ≥ 25% 이고 1·2위 차이 ≥ 8%, 아니면 '?' 표시)
     → 질문 흐름으로 후보 다시 고르기 → 사용자가 낱말 블럭을 눌러 고름 (고른 순서대로)
     → 문서 말로 바꾸기 (머리 + 보호 → 안전모, 입다 → 착용) → 비슷한 질문 3개 + 맨 뒤에 고른 낱말을 이어 붙인 블럭 (항상)
     → 질문 블럭을 누르면 팝업이 닫히고 입력창에 들어감 (보내기는 사용자가)
```

- 영상은 기기 밖으로 나가지 않는다.
- 시험 페이지 위쪽 입력창·카메라 버튼은 본 화면 흉내다 (카메라 버튼으로 팝업 열기·닫기).
- 화면은 기본 설정(아래 '지금' 열)으로만 동작한다. 단계별 끄고 켜기는 평가 페이지에서 설정을 하나씩 바꿔 비교한다.
- 화면에는 손 점·선만 흰색으로 그린다 (몸 점은 인식에만 씀).

## 개선 내용 (예전 = 팀원 SignBridge 방식)

| # | 개선 | 예전 | 지금 |
|---|---|---|---|
| 1 | 낱말 끊기 | 0.25초마다 최근 **48프레임**(느린 기기면 10초어치)을 보고, 같은 낱말 2번이면 확정 | 손을 올린 순간부터 내리거나 멈출 때까지를 한 낱말로 잘라 **한 번** 인식 (`Segmenter`) |
| 2 | 평가 | 없음 | 관절 점만 녹화(영상 없음) → `eval.html` 이 설정 10가지로 다시 돌려 낱말·질문 정확도 비교 |
| 3 | 속도 | Holistic (얼굴 468점까지 계산), 화면 스레드 | 가벼운 모드(몸 lite + 손만, 손은 몸 손목에 가까운 쪽으로 왼·오른 구분, **기본**) · 작업자 스레드. 화면의 점·선은 떨림 줄이기 전 값으로 그려 늦게 따라가지 않게 |
| 4 | 확신 판단 | 산업안전 단어 안에서 확률을 다시 나눠 부풀려짐 (≥ 60%) | 전체 단어 기준 확률 + 1·2위 차이. 확실하지 않으면 '?' |
| 5 | 떨림·끊김 | 없음 | One Euro 필터, 손 끊김 150ms 메우기 (`FrameCleaner`) |
| 6 | 후보 다시 고르기 | 없음 | 낱말마다 후보 5개 중 우리 질문들에 같이 나오는 조합을 위로 (`rerank`) |
| 7 | 새 낱말 | 모델에 없는 말은 못 함 | 낱말마다 예시 5개 → 모델 출력 모양이 가장 비슷하면 그 낱말 (재학습 없음, `web/sign/custom_words.json`). 가르치는 화면은 지금 빠져 있음 |
| 8 | 깊이(z) | 사용 | 끄고 켜며 비교 (평가 페이지) |
| 9 | 왼손잡이 | 오른손잡이 수어로 배운 모델 그대로 → 왼손잡이는 잘 못 알아들음 | 낱말마다 좌우를 뒤집은 것도 인식하고, 어느 쪽이 더 확실했는지를 카메라를 켠 동안 쌓아 판단 (`Handedness`) |
| 10 | 준비 시간 | 단어 목록 → 인식 모델 → 엔진 → 몸 모델 → 손 모델을 차례로 | 인식 모델과 관절 점 엔진을 동시에 준비, 인식 모델은 26MB → 14MB (`scripts/model/shrink_sign_model.py`) |

## 평가 (`/sign/eval.html`)

1. 관절 점 녹화 파일(JSON)을 준비한다. `/sign/` 의 녹화 화면은 지금 빠져 있어 가짜 녹화(아래)만 있다
2. 평가 페이지에 파일들을 넣으면 설정 10가지(새 방식·예전 방식·하나씩 끈 것)로 다시 돌려 낱말 찾은 비율·맞은 비율·질문 1순위/3순위 정확도

**가짜 녹화로 확인** (`data/eval/sign_synthetic/`, `python scripts/eval/make_sign_synthetic.py` — 우리 아바타 동작 데이터를 웹캠 관절 점 모양으로 바꾼 것, 예시 질문 5개):

| 설정 | 낱말 찾음 | 낱말 맞음 | 질문 1순위 | 질문 3순위 안 |
|---|---|---|---|---|
| 새 방식 (모두 켬) | 80% | 87% | 80% | 100% |
| 예전 방식 (팀원 그대로) | 17% | 40% | 0% | 20% |
| 예전 방식 + 산업안전 단어만 | 45% | 73% | 20% | 40% |
| 낱말 끊기만 예전 | 30% | 50% | 20% | 40% |
| 산업안전 단어만 끔 | 58% | 58% | 60% | 100% |
| 떨림 줄이기 끔 / 후보 다시 고르기 끔 | 80% | 80% | 80% | 100% |

⚠ 가짜 녹화는 사람의 웹캠보다 훨씬 깨끗하고, 동작 일부는 인식 모델의 학습 자료(AI Hub)와 겹칠 수 있어 **실제 정확도가 아니다.**
설정 사이의 차이(특히 낱말 끊기·산업안전 단어만)를 보는 용도. 실제 값은 팀원 녹화로 다시 재야 한다.
확신 판단·깊이·새 낱말은 가짜 녹화에서는 차이가 없었다 (새 낱말은 가르친 것이 없음).

### 낱말 하나씩 + 웹캠에서 흔한 문제 흉내 (`scripts/eval/sign_bench.py`)

동작이 있는 낱말 176개를 하나씩, 웹캠에서 흔한 문제를 흉내 낸 변형 9가지로 만들어(1,584개) 실제 `core.js` 를 브라우저에서 돌린다.

```bash
uvicorn api:app --port 8000 &
python scripts/eval/sign_bench.py                       # 기본 설정
python scripts/eval/sign_bench.py '{"끔":{"mirror":false}}'   # 설정을 바꿔 비교
```

| 변형 | 낱말 맞음 (1위) | 5위 안 | 왼손잡이 대응 끔 (1위) |
|---|---|---|---|
| 그대로 (30fps) | 53% | 60% | 53% |
| 15fps / 10fps | 51% / 51% | 58% / 57% | 51% / 51% |
| 천천히 + 15fps | 53% | 61% | 54% |
| 떨림 | 52% | 57% | 52% |
| 손이 0.2~0.35초 안 잡힘 | 52% | 58% | 53% |
| 작게·치우쳐 찍힘 | 52% | 59% | 52% |
| 느린 기기 + 떨림 + 끊김 | 53% | 59% | 55% |
| **왼손잡이 (좌우 반대)** | **47%** | **55%** | **24%** |
| 전체 | 52% | 58% | 50% |

- 왼손잡이 대응으로 왼손잡이 수어는 24% → 47%, 오른손잡이 수어는 거의 그대로 (±2%p, 낱말 4개를 이어서 한 것으로 계산)
- 인식 모델을 14MB 로 줄인 뒤에도 표의 값은 같다 (1위 낱말 일치 100%)
- 효과가 없어 넣지 않은 것: 프레임 사이 보간으로 길이 맞추기, 앞뒤를 잘라 여러 번 인식해 평균, 낱말 안의 손 끊김 메우기,
  손 움직임으로 주로 쓰는 손 정하기 (오히려 떨어짐)
- 절반쯤만 맞는 것은 우리 동작 자료가 인식 모델이 배운 수어와 다른 낱말이 많기 때문 — **사람이 한 수어의 정확도는 아직 재지 못했다**

| `web/sign/eval.html`, `eval.js` | 평가 페이지 |

| `web/sign/models/holistic_landmarker.task` | 관절 점 모델 (14MB) |

| `web/sign/lib/ort/` | ONNX Runtime Web 1.27.0 wasm (MIT) |
| `web/sign/domain.json` | 산업안전 단어 533개(말 270개), 수어 → 문서 말, 대체 표현 거꾸로, 질문 후보 49개 — `python scripts/data/build_sign_input_vocab.py` |

본 화면 첫 로딩에서 약 28MB 를 받는다 (압축 전 52MB: 인식 모델 14 + 관절 점 모델 14 + 라이브러리 25). 한 번 받은 기기는
오프라인 저장(`web/sw.js`)에 들어가 다음부터는 받지 않고, 인터넷이 없어도 카메라 수어 입력이 된다 (`docs/offline.md`).

## 산업안전 단어만

모델의 13,576개 중 우리 서비스에 나오는 말(동작사전·단어표·대체 표현·예시 질문·모범 답안·평가 질문의 낱말 + 질문할 때 쓰는 말)만 남겨
그 안에서 고르게 한다. 헷갈리는 후보가 줄어 정확도가 오를 것으로 보지만, **실제 수어로 잰 값은 아직 없다** (평가 페이지에서 끄고 켜며 비교).

모델에 없는 우리 말: 안전모·안전화·장갑·귀마개·보안경·교체·정화통·작업·착용·소음·교육·세척 등.
→ 있는 낱말 조합(머리 + 보호 → 안전모)이나 비슷한 말(입다 → 착용, 바꾸다 → 교체)로 문서 말을 찾는다.

## 남은 일

1. 실제 사람 녹화로 정확도 재기 → 기본 설정 정하기 (녹화·새 낱말 가르치기 화면은 빠져 있어, 필요하면 따로 녹화 방법을 만들어야 함)
2. 모델에 없는 산업안전 낱말(안전모·장갑·귀마개·정화통 등)의 예시를 `custom_words.json` 에 모으기
